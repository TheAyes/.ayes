# Minecraft servers on io

Declarative Minecraft hosting via [nix-minecraft](https://github.com/Infinidoge/nix-minecraft)
(flake input, module + overlay wired up in `flake.nix` / `hosts/io/configuration.nix`). Server data lives in
`/srv/minecraft/<name>` (`services.minecraft-servers.dataDir`), each server runs as systemd unit
`minecraft-server-<name>` under the `minecraft` user.

## Layer model

Broad → specific; every layer only overrides what it needs (`lib.mkDefault` in the baseline):

| Layer           | File                  | Provides                                                                                              |
|-----------------|-----------------------|-------------------------------------------------------------------------------------------------------|
| Host protection | `protection.nix`      | fail2ban jails + connection rate-limiting, auto-generated for every server with `openFirewall = true` |
| Global baseline | `baseline-server.nix` | JVM flags (G1 tuning), heap sizing, whitelist/ops admin entry, sane server.properties                 |
| Pack base       | `<pack>/default.nix`  | Fabric/MC version, per-server heap sizes, imports the server files                                    |
| Server instance | `<pack>/<server>.nix` | port, gamemode, difficulty, max-players, firewall exposure                                            |

`example/` is a disabled copy-paste template for a new pack.

The convention is a **live/dev pair per pack**: `aethyria` (port 25565, 16G heap)
and `aethyria-dev` (port 25575, 8G heap, max 1 player, never firewalled).

## The live⇄dev workflow (`mc-world-sync`)

Defined in `modules/home-manager/mc-world-sync/`, enabled in `users/ayes/home.nix`
(`programs.mcWorldSync`). Gives you two commands:

- **`mc-world-pull aethyria`** — live → dev. Stops dev, backs up dev's current state to
  `/srv/minecraft/.world-backups/`, copies **world + content**
  (`world*`, `mods`, `config`, `defaultconfigs`, `kubejs`, `scripts`), fixes ownership, restarts dev. If live is
  *running*, it needs RCON to `save-off` /
  `save-all flush` first — **and refuses to copy without RCON** (see gaps below). With live stopped it copies at-rest,
  no RCON needed.
- **`mc-world-push aethyria`** — dev → live, **content only, never the world**
  (hard-coded safety). Asks for confirmation, stops both, backs up live content, copies, restarts live only.

So the intended development loop is:

```
edit mods/config on dev  →  test on aethyria-dev (:25575)  →  mc-world-push aethyria
                                    ↑
                 mc-world-pull aethyria  (refresh dev with the real world)
```

Identity files (`server.properties`, `whitelist.json`, `ops.json`, `eula.txt`)
are never synced — those are generated by nix from this directory.

## Current state & what's missing

### 1. The servers crash on launch: wrong Java version ← the blocker

`/srv/minecraft/aethyria/fabricloader.log` (both live and dev, last attempt 2026-08-09):

```
UnsupportedClassVersionError: net/minecraft/bundler/Main has been compiled by a more
recent version of the Java Runtime (class file version 69.0), this version of the
Java Runtime only recognizes class file versions up to 65.0
```

Class file 69 = **Java 25**; `pkgs.temurin-jre-bin` is Temurin **21** (65). Minecraft 26.2 requires Java 25. Fix in
`aethyria/default.nix`:

```nix
package = pkgs.fabricServers.fabric-26_2.override { jre_headless = pkgs.temurin-jre-bin-25; };
```

(`temurin-jre-bin-25` = 25.0.3 in the current nixpkgs pin. The baseline's default package — fabric-1_20_1 on Java 21 —
is fine; packs on modern MC must override.)

### 2. The whole module is currently disabled

`hosts/io/configuration.nix` has `./minecraft-servers` (and `./fail2ban.nix`)
commented out in the working tree — presumably to stop the crash loop. Once the Java fix is in, re-enable
`./minecraft-servers` and rebuild. Note the coupling:
`protection.nix` only *defines* fail2ban jails; `fail2ban.nix` is what enables the fail2ban service, so it must come
back before any server goes public.

### 3. No RCON configured

`mc-world-pull` against a *running* live server needs RCON (it's also generally useful — `mcrcon` is already installed
host-wide). Nothing sets it. Add to the live server (keep it localhost-only; the firewall never opens it):

```nix
serverProperties = {
  enable-rcon = true;
  "rcon.port" = 25585;        # NOT 25566 — that's aethyria-dev's game port!
  "rcon.password" = "...";    # ideally via sops + nix-minecraft's mkDefault escape hatch
};
```

### 4. No mods/content — "Aethyria" is currently vanilla Fabric

`/srv/minecraft/aethyria/` contains only a crash log: no `mods/`, no `config/`, no world yet (a world generates on first
successful start). The sync workflow moves content between live and dev but nothing *creates* it. Two options:

- **Imperative** (quickest): drop jars into `/srv/minecraft/aethyria-dev/mods/`, test, then `mc-world-push aethyria`.
  Keep `chown -R minecraft:minecraft` in mind (the sync commands do this for you).
- **Declarative** (nix-minecraft native): use the per-server `symlinks` /
  `files` options so mods are pinned in the flake, e.g.

  ```nix
  services.minecraft-servers.servers.aethyria.symlinks = {
    "mods/fabric-api.jar" = pkgs.fetchurl {
      url = "https://cdn.modrinth.com/data/P7dR8mSH/versions/.../fabric-api-....jar";
      hash = "sha256-...";
    };
  };
  ```

  This also supports whole packwiz packs (`nix-minecraft`'s `fetchPackwizModpack`). Declarative content makes live and
  dev identical by construction — the push/pull workflow then matters mainly for the world and hand-tuned configs.

### 5. Before going public (later)

- `openFirewall = true` on `aethyria.nix` — protection.nix picks it up automatically (fail2ban jails + 5 conn/min rate
  limit).
- Whitelist currently contains only the admin; add players in `aethyria.nix`.
- Backups exist only as side-effects of pull/push (`.world-backups/`); consider a scheduled backup (restic timer or a
  cron'd `save-off; save-all flush; tar; save-on`)
  before real players build things.

## Quick reference

```bash
systemctl status minecraft-server-aethyria        # live
systemctl status minecraft-server-aethyria-dev    # dev
journalctl -u minecraft-server-aethyria -f        # follow logs
mc-world-pull aethyria [--no-start]               # live -> dev (world + content)
mc-world-push aethyria [-y]                       # dev -> live (content only)
mcrcon -H 127.0.0.1 -P <rcon.port> -p <pass>      # console access (once RCON is on)
```
